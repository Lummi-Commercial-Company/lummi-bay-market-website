Promos that expire by themselves

Promos are documents with a date window, not slots authored into a page. A page renders whatever is live for it — any number, on any page. Nothing is scheduled, so nothing can fail to fire: the window is compared against the clock per visitor, so a promo ending at noon is gone at noon whether or not anyone is watching.

Scrub past Monday 6am to see the ended state

Any number, any page

placement says where a promo appears; nothing is reserved. The cap is structural rather than a number in the code: the region is a list of rows, each row holds one to four across, and rows are capped at six per page. Promos past the available slots stay live in the data and take a slot as earlier ones expire, in priority order — so a busy week queues instead of growing the page without limit.

Zero live renders nothing

Scrub to a moment with no live promos: no region, no gap, no empty grid. The dashed box you see is a review aid and does not exist on the real page.

Expiry hides the landing page — it does not delete it

Deleting it would 404 every shared link, printed QR code and search result, which reads as a broken site rather than a finished offer. Instead the page keeps its URL, drops out of the sitemap, goes noindex, and says the offer has ended.

That is also what makes reactivation possible — a deleted page cannot come back.

The button label is a field, not a fixed string

Every promo here carries its own — “See the menu”, “Get the app”, “How it works”. A button that says the same thing on all of them tells a reader nothing about which one to press, and a screen reader announces a list of identical links.

It defaults to “See details” when an editor leaves it blank, so a promo is never published with an unlabelled button. Signed off 16 September 2026 — ADR 0023.

The fields, as the CMS shows them

Every promo on this page is one document with these fields and no others — the list of record is ADR 0018 §2, and this page is built from it. A promo is a form with fixed slots, not a builder: staff write the words and pick the dates, and the layout is not theirs to lose.

  • eyebrow — the small label above the headline. First of the three text fields
  • headline — the offer, 28 characters or fewer. The counter in the CMS is advisory; nothing enforces it at render. Also the document’s name in the Tina list, so a promo is findable by what it says
  • cta — the button label, editable per promo, defaulting to “See details”. Third text field — see the note below
  • image + alt — one 2400 × 1350 master, subject inside the centre 2400 × 480 strip. Not two crops: the phone slot is 16:9, so the master already is the phone crop
  • link — a reference to an infoPages document. Both the image and the button go there
  • startsAt, endsAt — the window, both optional. No start means already running; no end means until turned off
  • active — the kill switch. False beats any date; true never overrides one
  • placement — which pages it appears on
  • priority — who takes a slot first when more are live than there is room for. Ties go to the soonest endsAt, then to headline
  • body — removed. Three text fields, every slot and every device (ADR 0023). The body line cost a flat 24px of picture in every slot before a word was typed
  • width — removed. The layout belongs to the row, which re-divides when a promo expires. A width on the promo cannot

The list of old promos is the CMS

TinaCMS already lists every document in a collection with create, edit and delete. Reactivate is extending endsAt; deactivate is active: false, which beats any date. State is derived from the dates and never stored, so two fields can never disagree about the same fact.

Delete is safe

The CMS is git-backed (ADR 0002), so a deleted promo is still in the history and recoverable. Worth telling staff — it makes delete a button rather than a decision.

All copy and offers here are invented

The four promos, their dates and the landing page body were written to make the mechanism legible. No real offer is described, and deliberately no numbers — so nothing here can be screenshotted as a price.
