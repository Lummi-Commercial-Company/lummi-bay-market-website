Header logo — PNG, in the real header

The logo ships as PNG. This page loads the approved rasters unmodified from /public/brand/ into the header the site actually uses, at the dimensions ADR 0006 and ADR 0010 fix.

Decision — PNG only, no SVG. The supplied vector's paddle rendered pale, with a smooth gradient and no wood grain, where the approved raster's paddle is saturated cedar with visible grain. The logo is locked, so a mismatch is disqualifying rather than a preference, and ownership ruled the vector out.

The vector is kept as a master in assets/brand-source/logo-market.svg, which is never served. Nothing under public/brand/ references it. If a corrected vector arrives later this decision is worth revisiting — vector is still the better format when its colours are right.

Does PNG hold up at 3× device pixel ratio?

This is the only real cost of dropping vector, so it is measured rather than assumed. A file is sufficient when its ink width is at least three times the CSS width it is displayed at.

PNG is sufficient everywhere the logo currently appears, to 3×. Two things to know rather than fix. The desktop header lands at 99.4% of a true 3× sample — 334px of ink against 336px wanted, a 0.6% shortfall no eye resolves. And the reversed file has no headroom beyond that: any future use of the reversed lockup larger than ~111px CSS (a dark hero, a footer lockup, an OG image) would upscale. The cheap insurance is one more export at 1008 × 360 — 3× the current canvas, same art.

What PNG gives up, honestly

Print and large format. Signage, vehicle wraps and anything above ~500px need the vector. Keep assets/brand-source/ populated for that; it is a separate problem from the website.

Recolouring and masking. A PNG cannot be tinted in CSS or used as a mask-image. Nothing in the locked architecture asks for that — and the logo may not be recoloured anyway, so the constraint costs nothing here.

Weight. 15.6 KB reversed, 27.6 KB navy. Both trivial, both cacheable, both served once per visit.
