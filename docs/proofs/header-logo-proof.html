The problem: the file's box is not its art

The SVG canvas is 336 × 120 — exactly the 2.8:1 ADR 0006 assumes. But the ink sits in the top of that box and stops well short of the bottom edge. Dashed outline is the canvas the layout sizes; cedar outline is where the ink actually is.

Same nominal box, different art inside it. Sized to the same width, the SVG reads visibly smaller and sits higher than the PNG — 30.2px of ink against the PNG's 36px at a 112px box. Vertically centring the box does not vertically centre the logo.

Open items this proof raises

1. Which paddle is authoritative? The vector's paddle is pale and ungrained; the raster's is saturated cedar. The logo is locked, so this is not a preference — one of the two files misrepresents the approved art and ownership has to say which.

2. Re-export with the artboard trimmed to the art. That removes the 21.8-unit bottom gap, makes the file's box its art, and lets the header size the logo without a per-file fudge factor. Until then any header CSS carries a magic number.

3. There is still no vector for light grounds. This file is the reversed lockup — on --lb-bone the white wordmark all but vanishes. The home hero and /rewards sit on light ground and need the navy vector.

4. ADR 0006's 2.8:1 is right about the canvas. It is the ink that varies between files. The header height does not need re-opening on the strength of a ratio, but it does need one authoritative file to measure.
