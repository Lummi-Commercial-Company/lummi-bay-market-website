More than one main page

The main page is not a route. It is a document, and more than one may exist — so a seasonal or campaign version is built in full, reviewed on its own URL, and switched live by changing one field. The one it replaces stays where it is, ready to switch back to.

Pick one below. The settings file and the live preview both follow.

content/settings/site.json 
{
  "homePage": "main-pages/standard"
}
/ → standard /preview/long-weekend /preview/storm

A pointer, not a flag

One reference field in a settings singleton names the live page. A live: true boolean on each document would let two of them claim it at once, and there is no sensible answer for what the site should then do.

Nothing else moves

Header, fuel block, waterline, footer and back-to-top come from the layout. Switching main pages changes the hero and the promo set — the site's furniture is identical before and after, because no page owns it.

The old one is not deleted

Switching away leaves the previous main page as a document. Reverting is the same one field, changed back. That is the difference between this and editing the live page directly.

A switch is a rebuild

The site is static. Changing the pointer commits to git, which triggers a deploy — so the swap takes a build, not a page refresh. Fine for a planned campaign; not a lever to pull for something happening in the next five minutes.

Preview URLs need a decision

A main page that is not live has to be reviewable somewhere. Vercel gives every branch a preview deploy, which may be enough — or the collection gets a real /preview/<slug> route that is excluded from search engines. The second is friendlier for a non-technical reviewer and is more to build.

All copy here is placeholder

The three headlines and their promos were written to make the switch legible. Real campaign copy comes from whoever owns the promotion.
