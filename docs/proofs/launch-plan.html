Part 3

How the site gets updated

There is no database and no admin server. Content is a set of text files in the project's repository. Editing content changes a file; changing a file rebuilds the site; the rebuild publishes. The three ways in are three doors onto that same act.

What the model buys you

Every change is a commit — who, what, when, and a one-click revert. A wrong fuel price is undone by reverting, not by remembering the old number.

Nothing to back up, because the repository is the backup. No database, no CMS server, no patching, no monthly database bill.

The site cannot go down because the CMS did. Published pages are static files. If the editor is unreachable, staff cannot edit — visitors never notice.

Limits to know before training staff

Two editor logins on the free tier; a third person costs $29/mo. Pick the two before provisioning — shared logins destroy the per-person history that is half the point.

Staff edit content, not layout. Prices, hours, copy, promos, the Careers link. Not sections, colours, or new pages. That is deliberate: handing layout to non-designers is harder for them, not easier.

A failed build leaves the old site up. Visitors see the previous page rather than an error — but someone has to notice, so build failures need to reach a human.

The one real trade-off

Publishing takes one to two minutes, and a cached page can lag a little further. For hours, promos and store copy that is irrelevant.

For fuel prices it is a genuine constraint. If a posted price has to be correct to the minute, this stack is the wrong shape — and that is worth saying now rather than discovering it at launch. Everything else about the git-backed model is upside; this is the part that costs something.

Scheduling: can a promo take itself down at noon?

Yes — but it costs $20/mo, and that is worth knowing before it is promised to anyone. A static page does not know what time it is; it was rendered when someone last saved. Something has to happen at noon.

Why fuel prices only exist once

All eight prices live in a single file. The price block, the condensed bar, the panel and the Fuel Prices page all read from it, so changing the number once changes it everywhere. There is no second copy anywhere in the site, and that is enforced by the data model rather than by anyone remembering to update both places.
